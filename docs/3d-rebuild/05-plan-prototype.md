# 2D 楼层平面原型（结构动作传播 + 分区空间语法）

> 目的：在写 Unity 之前，先用纯 Python 出俯视图，验证"房间形状由结构动作传播、而不是给矩形撒斜线"能否真的消除"办公室格子间"观感。
> 代码：`tools/plan-proto/plan_proto.py`（单文件，无第三方几何库，多边形裁剪/轮廓追踪/DP 简化全手写）
> 运行：`cd tools/plan-proto && python plan_proto.py --out ./out`（约 20 秒）

## 1 生成顺序（顺序本身就是结论）

   外廓(45° 截角 + 边缺口)
   → 斜向主脊（一条贯穿全层的斜廊，5.6m 宽，标"主脊"）
   → 地标：旋转大厅 / 环形核心筒 / 中庭挑空（每个自带环廊 + 一条支廊接回主脊）
   → 电梯核心筒（沿主脊两侧贴边布置，斜纹填充）
   → 主廊 vcuts/hcuts（轴对齐贯穿廊，4.6m，遇地标自动挪位）
   → 分区 BSP（走廊把剩余楼板切成若干块，每块用自己的一套空间语法）

**地标必须放在主廊之前。** 早期版本把地标放在主廊之后，判据 `(地标 & 走廊).any()` 在"贯穿全层的主廊"下永远成立，导致地标零出现（F11/F21 的中庭连续多轮没生成）。改成先放地标、再让主廊避让，三张地标图才全部出现。

**环廊不是装饰。** 地标必须能直接从环廊进入，不能穿房间进去；环廊宽 5.0m（`ring_w`），早期 3.4m 在总图上读不出是走廊。环廊还必须有一条 `link_to_spine` 支廊接回主脊，否则是孤岛。

## 2 空间语法库（GRAMMAR_LIBRARY）

| 语法 | 参数（max_room / 长宽比 / 权重） | 读感 |
|---|---|---|
| 阵列网格 | 330 / 1.6 / w3 | 标准办公单元 |
| 小隔间 | 210 / 1.4 / w3 | 居住/宿舍尺度 |
| 管廊窄间 | 250 / 2.2 / w2，局部廊 2.2m | 设备/后勤 |
| 长条仓区 | 1200 / 9 / w2，strip_w 10m | 物流货架带 |
| 无柱大跨 | 2400 / 3.4 / w1，禁局部廊 | 展厅/厂房 |
| 展厅 | 700 / 2.4 / w2，禁局部廊 | 大空间 |
| 斜网 +14° | 430 / 4 / w2 | 斜柱网办公楼 |
| 斜网 −9° | 520 / 4.5 / w2 | 另一个方向的斜柱网 |

每块 `pick_grammar` 权重 = `w / (1 + 2*used)`，同层用过一次权重就掉，避免一层里重复出现同一套语法。切分轴用该块自己的投影轴 `ax/ay`，所以斜网块的墙真的斜，而不是"斜线框套矩形"。

## 3 两组 A/B 的结论

### 3.1 斜柱网（`ab_grid.py`，同 seed 7071）

| | 房间 | 矩形 | 梯形 | 多边形 | 非矩形 | 走廊 |
|---|---|---|---|---|---|---|
| A 正交柱网 | 67 | 38 | 11 | 17 | 44% | 22% |
| B 倾斜柱网 14° | 78 | 0 | 51 | 26 | **100%** | 17% |

**结论：整层柱网转 14° 是无效方案。** 非矩形率 100%，但所有墙互相平行、没有尺度差异，读起来就是"把整层平面转了一下"，一格都没打破。这个方向已废弃。

### 3.2 分区空间语法（`ab_zoning.py`，同 seed 7071）

| | 房间 | 非矩形 | 走廊 | 分区 |
|---|---|---|---|---|
| A 一套语法铺满 | 157 | 32% | 22.2% | 8 |
| B 分区各用一套语法 | 129 | **57%** | 19.5% | 8 |

**结论：真正打破同质化的是"走廊分隔的每个分区各用一套空间语法"。** A 的非矩形率不算低，但整层房间尺度统一、排布节奏一致，仍然读作格子间；B 在同一块楼板上有三种墙向、三种房间尺度，读起来是"几个不同时期/不同功能扩建出来的翼楼"。

### 3.3 现状 vs 结构动作传播（`plan-proto-compare.png`）

同 hex 尺寸 200×160m、同 seed 7071：纯矩形 BSP 79 间全矩形；结构动作版 129 间、非矩形 57%、五套语法分区。

## 4 六层实测（`plan-proto-floors.png`）

| 层 | 结构动作 | 房间 | 非矩形 | 走廊 |
|---|---|---|---|---|
| F02 物流层 | 斜脊 + 长条仓区 | 138 | 20% | 13.1% |
| F07 数据层 | 斜脊 + 45° 旋转大厅 | 129 | **57%** | 19.5% |
| F11 居住层 | 斜脊 + 八面中庭挑空 | 204 | 13% | 11.2% |
| F15 医疗层 | 斜脊 + 环形核心筒（8 扇形病区） | 129 | 37% | 9.8% |
| F18 中转层 | 斜脊 + 环筒 + 旋转大厅 | 116 | **72%** | 15.2% |
| F21 观景层 | 斜脊 + 大中庭 + 大跨展厅 | 102 | 25% | 13.7% |
| baseline | 无（纯 BSP） | 79 | 0% | — |

F11 非矩形率偏低（13%）是因为居住层用「小隔间 + 阵列」两套都是规整语法、且房间数多（204 间，小房间多则内部矩形多）。这是取舍不是 bug：要"迷宫感"就把语法往斜网/长条调，要"居住单元可读"就保持规整。

## 5 已知不足 / 下一步

1. **还没移植进 Unity。** `FloorGenerator` 目前仍是"外廓多边形化 + 房间轴对齐 BSP"，没有主脊/地标/分区语法。
2. **门只开向走廊。** 小于 380 m² 的房间只留一道门；没有走廊邻接才开一道套间门；都没有则降级为实心体量。真实建筑里大量房间是套间串联的，这块可以再放开。
3. **局部走廊是直的。** 只在两端都已连通走廊的块里插，避免死胡同，但也意味着分区块内部没有 L 形/折线走廊。
4. **多层竖向对位没做。** 楼梯/电梯核心筒目前按每层主脊独立摆放，跨层位置不保证对齐。双层玩法（M2）需要先解决这个。
5. **孤岛风险。** 分区语法 + 局部走廊之后的房间可达性没有做全图连通性验证（用洪水填充从走廊穿门查一遍即可，但每层成本不低）。
